# CLAUDE.md — лендинг shlenskov.pro

Личный сайт-портфолио Алексея Шленскова (Python backend-разработчик): услуги, работы, форма заявки.
Статические HTML-страницы + маленький FastAPI-бэкенд, который только отправляет заявку на почту.

## Структура

```
index.html            — главная: hero, стек, услуги, «Мои работы», форма
style.css             — единственный файл стилей (тёмная тема, CSS-переменные)
projects/*.html       — страницы проектов
assets/img/<проект>/  — скриншоты проектов
assets/js/lightbox.js — увеличение скриншота по клику
backend/main.py       — FastAPI, один маршрут POST /send (SMTP Яндекса)
nginx/landing.conf    — конфиг nginx для прода
NGINX.md              — заметки по настройке nginx и SSL
```

Сборки нет: никаких фреймворков, шаблонизаторов и npm. Шапка, футер и лайтбокс продублированы
в каждой странице — при правке каркаса менять во всех файлах `projects/`.

## Скриншоты

Снимаются с живых сайтов в Chrome под залогиненным пользователем владельца.

- Вход на fieldlog.ru сохранён для адреса без `www`; на `www.fieldlog.ru` сессии нет
  (удобно для кадров входа и регистрации).
- Окно браузера широкое (2560 px), поэтому перед кадром ставится `document.documentElement.style.zoom = 1.6`.
  При зуме координаты клика нужно умножать на 1.6 — надёжнее кликать через JS (`element.click()`).
- Размер кадра 1568×744…779, JPG, без рамки браузера.
- Персональные данные размываются прямо на странице (CSS `filter: blur(7px)`) до снимка:
  имена и логины, email, телефоны, аватары; на fieldlog.ru также названия объектов, дорог и систем.
  Название организации «1520 Сигнал» и тексты задач владелец оставляет видимыми.
- Для кадров с формами (интервью, резюме в PrepStats) используются вымышленные данные —
  «Иванов Иван Сергеевич», `example.com`, ООО «Пример».
- Запуск интервью и создание резюме в PrepStats тратят дневной лимит (1 в день на бесплатном тарифе)
  и оставляют запись в аккаунте владельца — предупреждать заранее.

## Локальный запуск

- Сайт: открыть `index.html` двойным кликом. При `file://` форма шлёт запросы на `http://localhost:8000`.
- Бэкенд: из папки `backend` — `..\.venv\Scripts\python.exe -m uvicorn main:app --reload`.
  Нужен `.env` в корне (`YANDEX_LOGIN`, `YANDEX_PASSWORD`, `RECIPIENT_EMAIL`, `ALLOWED_ORIGINS`).
  `GET /` у бэкенда отдаёт 404 — это нормально, маршрут один.
- Проверка вёрстки по http: `python -m http.server 5500` из корня (форма при этом не работает).
- Отправка формы уходит настоящим письмом — не тестировать без просьбы.

## Прод

- Домен `shlenskov.pro`, сервер — каталог `/var/www/landing` (клон репозитория).
- Системный nginx отдаёт статику прямо из корня репозитория и проксирует `/send` на `127.0.0.1:8000`.
- Бэкенд — контейнер из `backend/Dockerfile` (python 3.12), `docker-compose.yml`.
- Деплой: push в `main` → GitHub Actions → SSH → `git pull` → пересборка контейнера `backend`.
  Статика обновляется самим `git pull`. Конфиг nginx деплоем не трогается.
- `root` у nginx — корень репозитория, поэтому новый файл в нём по умолчанию доступен по прямой ссылке.
  `nginx/landing.conf` закрывает скрытые файлы (`.env`, `.git`), папки `backend/` и `nginx/`, файлы `.md` и `.yml`;
  всё остальное публично. Конфиг на сервер копируется вручную — после его правки нужен `nginx -t` и reload.
